2. Method

The engine exposes a debug handle that steps the simulation deterministically and can hand the paddle to the built-in AI. Each automated round drives a real game: the countdown, serves, brick collisions, boost drops and pickups, level clears and life loss all execute exactly as they do for a player, with the renderer drawing every frame. Hands-on runs then covered input, screens and native behaviour that a script cannot judge.

5. Known limitations

  • Sound effects are synthesised; a recorded set is planned for the ship phase.
  • Fonts load from Google Fonts on first run; offline sessions fall back to system faces until fonts are bundled (ship phase).
  • Quality tiers were set by reasoning, not measurement; real-device profiling will tune them.
  • The iOS project uses a local copy of the Capacitor runtime package. Running npx cap sync ios restores the remote dependency; the README explains how to re-point it.
  • No analytics or crash reporting in 1.0, so production behaviour is not yet observable.
Automated runs are reproducible from the repository: open the game, then use the debug handle described in the README to step the simulation. Screenshots from each environment are retained with the project files.
